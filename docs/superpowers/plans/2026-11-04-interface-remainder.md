# План: всё оставшееся из аудита интерфейса

> **Для исполнителей:** задачи по порядку, через TDD (`superpowers:test-driven-development`), перед заявлением о готовности `superpowers:verification-before-completion`. Шаги отмечаются `- [ ]`.

**Цель:** владелец работает с ботом и моделью только через веб: всё, что ему нужно, есть на дашборде, а всё, чем нельзя пользоваться, удалено.

**Основание:** правило в `CLAUDE.md`, раздел «Интерфейс»; аудит от 2026-11-04.

## Глобальные ограничения

- Фоновые задания не мешают боту: одно задание за раз, низкий приоритет, проверка свободной памяти перед запуском.
- Журнал задания маскирует токены. Запускаются только задания из белого списка, параметры проверяются.
- Перезапуск дашборда прерывает задание: это честно показывается как «прервано».
- Удаление данных только после пробного прогона и с бэкапом.

## На что смотреть при проверке

1. Задание уже идёт: вторая кнопка не запускает второе.
2. Перезапуск дашборда посреди задания: статус «прервано», а не вечное «идёт».
3. Брокер недоступен при сверке: понятное сообщение, страница работает.
4. После чистки истории нет: вкладка не падает, тренер честно пишет, что данных мало.
5. Строки истории без стакана: в обучении нейтральные значения, а не нули.
